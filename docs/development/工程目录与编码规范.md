# 静读工程目录与编码规范

本规范自 2026-11-13 起生效，适用于 WDD 2026V1，经典 ESP32、无 PSRAM、240 × 416 单色墨水屏。目标是让接手者知道一项功能应该改在哪里、资源由谁释放，以及怎样证明改动有效。

**审核口径。** 下列规则适用于源码、资源和发布包。用工程现状核对硬件限制、磁盘格式和兼容行为。“必须”约束数据正确性、设备资源、对外兼容和交付内容。“建议”给出默认做法，涉及运行开销的取舍以本机测量为准。正式文件位于 `docs/development/工程目录与编码规范.md`，由根目录的 `AGENTS.md` 链接。

## 首要设计原则：本机性能优先

**在实现相同功能、保证正文与用户数据正确的前提下，优先选择这台 ESP32 上操作更快、内存留得住的方案。模块化、低耦合、DRY 和编码风格都服从这一原则。性能影响可忽略时，选更清楚、更容易维护的写法。** 这一优先级适用于设备上执行的代码。主机导入工具关注自己处理大文件的成本，源码目录和文档按可维护性组织。

| 需要取舍时 | 在本项目如何判断 |
| --- | --- |
| 读者等多久 | 记录输入来源和刷新完成时间。人工触摸、USB 注入应用触点、直接调用翻页函数分别标注计时起点。分别看大书首次开书与重开、停读再翻、连续快翻和跨章。记录样本数、中位数、P95（样本充足时）和最慢页，跨章单列。 |
| RAM 花在哪里 | 比较常驻开销、最紧张阶段的可用内部字节堆和最大连续块，再看关闭功能后能释放多少。更大的缓存若能缩短等待，且仍能开大书、切书和启动其他功能，可以采用。局部加速若使另一本书打不开，应缩减缓存或按需释放。 |
| 怎样判定“影响不大” | 对会改变执行路径或资源占用的改动，用同一设备、原卡、书籍位置、排版和缓存条件做前后对照。差异落在重复测量的正常波动内，关键慢页和内存余量也稳定，可按可读性选择。没有对照时标为待验证。纯命名、注释或目录整理，核对构建和行为即可。 |

**具体取舍。** 若统一 TXT 与 EPUB 的排版接口会多复制一页正文，可让两条热路径分别直接消费现有缓冲区，以同一组排版样例核对共同规则。若一个普通函数就能让侧键和触屏复用翻页逻辑，又没有增加分配或读卡，则保留这个函数。为性能保留专用实现时，在代码旁简要写明省下的操作、适用条件，以及哪项测试覆盖共同语义。

## 工程目录

| 路径 | 放什么、如何使用 |
| --- | --- |
| 根目录 | README、AGENTS、PlatformIO/CMake 配置、分区表与格式/忽略规则。README 给新读者第一条构建命令，AGENTS 给修改者入口和验证要求。 |
| src/main.cpp、src/board/ | Arduino 入口与板级硬件。引脚、面板波形、USB 诊断属于板级；桌面业务不引用 Arduino 头。 |
| src/ui/、src/reader/、src/storage/、src/learning/、src/network/ | 分别放页面与画布、分页与 EPUB、TF 数据、英语练习、局域网接口。按职责移动现有实现，不借搬家改 ABI 或拆出没有独立职责的新类。 |
| include/ | 被板端与桌面共用的接口；内部实现与私有头就近放在 src 对应模块。文件名唯一时保留现有 include 名，减少对下游的改动。 |
| src/generated/、web/、assets/ | src/generated/ 收纳固件编译需要的离线生成表和网页嵌入文件，web/ 保留网页源码，assets/ 按类别收纳可再生成这些资源的原始素材。修改输入时同步核对生成物。 |
| lib/、licenses/ | 保留实际编译的第三方库、上游布局及许可证；记录本项目的本地适配。不把 SDK 的发布包、测试私有书库或嵌套 Git 仓库带进来。 |
| tests/、scripts/ | CMake 主机测试、可复现的合成夹具与构建/导入/生成脚本。PlatformIO 目录可配置；现有 tests 保持单一入口，无需并存 test 和 tests。 |
| tf/ | 按卡上路径组织专供随卡分发的内容，如 fonts/、courses/、dictionaries/。tf/manifest.json 记录组包需要的文件，允许引用 assets/、licenses/ 中的原件。用户实际卡上的内容由用户管理。 |
| docs/ | 按下表归档当前文档，根 README 链接常用入口。开发过程材料保存在忽略的本地归档。 |
| .local/、.pio/、artifacts/、实机记录/ | 工具链、构建缓存、打包结果、设备备份、私有卡样本和日志；不跟踪。诊断产物不从 README、公共测试或发布包反向引用。 |

### 正式文档按读者查找的主题归档

docs/README.md 只做索引。每个主题保留一份权威说明，其他文档用相对链接引用。目录有对应文档时创建。迁移时同步修正 README、AGENTS、文内链接和配图路径。

| 路径 | 归档范围和例子 |
| --- | --- |
| docs/architecture/ | 系统如何工作，如阅读流水线、模块职责、内存预算。 |
| docs/hardware/ | WDD 2026V1 引脚、屏幕时序、电源和启动条件。 |
| docs/formats/ | 持久化或交换格式，如 TF 目录、阅读锚点、课包、缓存版本。 |
| docs/ui/ | 正式交互规范和覆盖全部页面的可点击设计稿（design/）；README 使用的原生固件渲染图放 images/。 |
| docs/development/ | 工程与编码规范、构建、测试和可重复使用的真机验证方法。 |
| docs/guides/ | 整机功能指南和资料导入说明。指南用到的公开实机配图放 images/；协议字段链接其权威说明。 |

例如，用户要知道“字体怎么装”，从 docs/guides/ 进入；开发者要知道“字体缓存用什么键、何时失效”，从 docs/formats/ 进入。分配多少 RAM、为什么采用该预算，由 docs/architecture/ 解释。三者互相链接，路径和数据格式只在对应的权威文档中定义一次。改变目录或格式时，在同一次修改里更新受影响的说明。

**设计、功能和说明同步。** 改入口、手势、按钮、等待或错误状态：先更新[可点击设计稿](../ui/design/README.md)，经审核后改固件；同一变更更新[完整功能指南](../guides/完整功能指南.md)、受影响的配图和回归。增加设备页面时，其 View 必须同时出现在设计稿和指南对应小节。改变导入格式、随卡内容或浏览器功能即使没有新页面，也要更新相应说明。纯内部重构若不改变用户行为，不需改写指南。README 首屏保留当前主要界面，通过相对链接引导使用者继续阅读。

**公开配图。** 使用示例书、示例课包、离线网络。区分桌面绘制、设备帧缓冲回读与面板实拍，后两者注明版本或采集日期。默认不使用旧实拍，原始图片及串口记录留在本地。实拍需专门为公开用途拍摄，画面不得出现真实网络、配对码、密钥、私人书目、反光中的人或桌面资料；去除定位等元数据并复核后再入库。暂时没有公开实拍时标明已有证据，不拿渲染图替代实拍。测试入口会核对页面覆盖、链接及插图原生规格，实际效果仍需人工看图。

逐轮评审稿、性能原始日志、版本截图拼图留在本地。一份旧报告兼有现行规则与测量过程时，提取仍有效的结论，写清机型、输入条件和验证方法，原报告留在本地。检验正式文档时，从干净克隆打开入口页，所有仓库内链接及配图均应可达。

### 原始素材、内置资源与随卡文件

| 路径 | 谁读取、何时使用 | 项目实例 |
| --- | --- | --- |
| assets/fonts/ | 开发机上的字形生成工具读取字体原件，记录来源、版本和许可。 | Atkinson Hyperlegible Next Medium 经离线栅格化，英语练习从固件读取生成的点阵。 |
| assets/icons/、assets/images/ | 有独立维护的图标或产品图像原稿时，按类型创建目录。算法直接绘制的图标保留绘制代码。 | 若以后从图标原稿生成点阵，原稿归 icons/，编译所需的生成表归 src/generated/。文档配图就近放在 docs/ 对应主题下。 |
| tf/fonts/ → 卡上 /fonts/ | 阅读器运行时打开用户选择的字体。用户可以直接增删卡上字体，随卡包只提供清单中的可选内容。 | 霞鹜臻楷可在阅读排版中选用；生成的字形缓存写入卡上的 /.jingdu/cache/。 |

一种字体兼作生成输入和随卡字体时，在工程中只维护一份有许可的原件。优先以 assets/fonts/ 为来源，生成工具和随卡清单共同引用它，打包时映射到卡上 /fonts/，同时带上许可。只用于生成内置字形的原件无需列入随卡清单。私有实卡、运行缓存及个人书籍存放在工程发布输入之外。

迁移生成器时记录输入文件、上游版本或文件摘要、许可、生成命令和输出。包括备用字体，例如英语音标还会用到 DejaVu Sans。清理第三方测试目录前，先查生成器是否直接引用其中的字库。普通固件构建可直接使用已跟踪的生成表；维护字体时才需取得原件、运行生成器。只搬动原件时，核对生成前后的字形度量和位图字节；生成文件里的来源路径可以随迁移更新。

### 随卡发布清单

`tf/manifest.json` 供电脑打包使用。每项的 `source` 相对于仓库根目录，`destination` 相对于卡根目录，也是 ZIP 的条目名。需要随附声明的资源通过 `notice` 引用包内的声明路径。多个文件可以共用同一声明。以下两项展示霞鹜臻楷的实际映射。

```json
[
  {
    "source": "assets/fonts/霞鹜臻楷.ttf",
    "destination": "fonts/霞鹜臻楷.ttf",
    "notice": "fonts/OFL.txt"
  },
  {
    "source": "licenses/霞鹜臻楷-OFL.txt",
    "destination": "fonts/OFL.txt"
  }
]
```

打包只读取逐文件列出的来源。来源缺失或解析到仓库外、目标含绝对路径或父目录跳转、目标重名（含仅大小写不同）、声明引用缺失，均应在产出发布包前报错。卡包保留设备已有的目录和文件名，使已保存的字体路径、课程选择等在源码重组后仍然有效。清单本身只在电脑使用。

## 模块化、低耦合与复用

在满足上述性能条件的实现中，按以下原则组织代码。

| 设计原则 | 评审时具体看什么 | 在静读中的用法 |
| --- | --- | --- |
| 高内聚 | 能否用一句话说清模块负责的决策？同一原因引起的修改能否集中完成？ | 页面组合控件和解释输入，阅读器决定下一阅读位置，显示驱动提交画面并报告刷新完成。改翻页策略应能在阅读器内验证。 |
| 低耦合 | 调用者提供哪些输入、观察哪些结果？能否替换 TF 文件或显示设备来测试业务？ | 侧键和触摸先解释成阅读意图。阅读器接收翻页请求并返回结果，UI 决定何时重绘。GPIO、中断和屏幕 BUSY 由板级管理。 |
| 单一事实来源（DRY） | 两段逻辑是否表达同一条规则，改其中一处是否必须同步改另一处？ | 侧键和触屏共用翻页规则；目录和书签列表可共用分页控件。书签保存失败须保住上一份有效记录，页缓存损坏可以丢弃重建，两者只共用底层校验或文件操作。 |
| 适度抽象 | 新接口是否隐藏了调用者不该知道的细节，或给板端和主机测试提供了真实替换点？ | 无状态计算优先用普通函数，有状态且负责释放资源时用对象。对“换页”的共同语义有把握时即可复用；遇到仅有两段长相相似的代码，先确认它们是否应一起演进。 |

模块间优先传递本次操作所需的值、引用或小接口。共享可写状态必须有明确所有者。只有调用关系确实需要异步时才引入事件队列或 FreeRTOS 任务，写明任务栈、缓冲区所有权、取消与退出条件。普通函数和源文件边界本身无需创建任务。每个 FreeRTOS 任务都有独立的栈。[Espressif 内存说明](https://docs.espressif.com/projects/esp-idf/en/stable/esp32/api-reference/system/mem_alloc.html)

## 编码与代码风格

| 范围 | 项目约定 |
| --- | --- |
| 源文件与文本 | 自有源码、脚本、配置和 Markdown 使用 UTF-8 无 BOM、LF、文件末尾一个换行。机器可读的命令、日志字段和格式标识用稳定的英文名，面向读者的文案用中文。导入书籍保留原始字节，在解码边界处理 UTF-8、GB18030 等编码。TXT 锚点记录原文件的字节偏移，EPUB 锚点记录阅读顺序项和该项解析后正文流的字节偏移。改变正文流表示时需检验旧进度与书签的兼容性。 |
| C++ | 板端和桌面共用代码以 C++17 为基线。以仓库的 .clang-format 为格式基准，Google 风格、2 空格、110 列、保留 include 顺序。分支和循环展开书写。类型用 UpperCamelCase，函数和变量用 lowerCamelCase，新增命名常量用 kUpperCamelCase。命名表达领域含义和单位，如 byteOffset、timeoutMs。保留磁盘字段、协议字段和上游标识的既有拼写。 |
| 函数、头文件与注释 | 每个函数围绕一个可描述的操作。分支代表不同职责时拆开，紧密的数据变换留在一起。头文件自行包含所需声明，减少跨模块暴露的可写字段。注释说明所有权、硬件时序、格式兼容和异常路径，数字上限写明来源。 |
| Python 与 Shell | Python 用 4 空格、snake_case、显式编码和上下文管理器。可复用逻辑放函数，CLI 处理参数和退出码。Shell 变量和路径加引号，失败要通过退出码传给调用者。构建与测试从干净克隆可运行，脚本通过参数或工程相对路径找输入。 |
| 生成资源与第三方代码 | 生成文件保留输入来源、生成命令和许可，修改输入后重建比对。自有代码的格式约定适用于日常改动。上游依赖保留原布局和风格，必要补丁限定在对应功能。 |

**规范依据。** 工程已配置 C++17、clang-format 和桌面 ASan/UBSan。命名、分层、错误语义及下面的资源责任是项目约定，维护时按受影响的路径核对。[C++ Core Guidelines](https://isocpp.github.io/CppCoreGuidelines/CppCoreGuidelines)

## ESP32 资源、时序和数据

- **内存与所有权。** 为文件、解压器、字体和预读画布指定唯一所有者与释放时机，优先用 RAII。按文件条目数、尺寸或解压长度分配前，必须验证上限、乘加溢出和读写边界。大目录优先分块或在 TF 上分段读写。必要的大块分配说明峰值与降级方式，关注可按字节访问的内部堆及最大连续块。操作结束、失败、换书和拔卡都要能释放已取得的资源。
- **交互与后台工作。** 分清触点收到、读卡、解压、排版、绘字和面板刷新完成。预读工作按可中断的小步推进，当前页、用户阅读锚点和已提交给面板的画面由前台维护。切书、跳目录或改排版时，尚未完成的预读必须作废。新增后台工作先给出单步预算和取消条件，再以真机测触点等待和内存峰值。
- **内存准入与诊断。** 普通字节缓冲按内部、可按字节访问的堆同时观测空闲总量和最大连续块。检查申请量与前台预留量之和时避免整数溢出。预检只反映当时的状态，通过后仍须处理实际分配失败。新增常驻缓冲或任务栈时，在受影响的工作负载记录峰值共存对象和任务剩余栈空间，在同一空闲状态重复切书或退出服务，看余量能否稳定。预留值由相应场景实测确定。[Espressif 堆内存说明](https://docs.espressif.com/projects/esp-idf/en/v5.5/esp32/api-reference/system/mem_alloc.html)
- **错误语义。** 分别保留格式错误、处理上限、运行时内存预检拒绝、实际分配失败和 TF 读写错误。条目估算超限应说明当前索引能力；连续块装不下必要缓冲或分配会侵占前台预留时，可先释放可重建缓存、缩小工作区或降级。日志区分请求字节数、连续块和预留量，无需为证明原因强行分配。后台失败走按需读取，保留已显示页的进度。
- **拔卡、切换与休眠。** 预读、写缓存和上传须能识别各自所属的卡与操作。切换或拔卡后，旧操作失效，迟到的结果不能写入新书、新卡或已释放的缓冲。正常休眠先收尾有界的必要写入，意外掉卡按上次有效记录恢复。允许在面板 BUSY 期间做有界预读，但驱动仍需使用的画布由提交方保留到完成或超时。涉及这些路径时，验证取消、超时或重新挂载后可继续操作。
- **持久化与兼容。** 缓存可重建，进度、书签和设置须可恢复。更新重要记录时先完整写入并校验，再切换有效版本。新二进制格式写明版本、字段宽度、字节序和尺寸上限，显式处理截断和旧版本。局域网传入的路径使用统一的允许规则，日志只记录排错所需字段。
- **验证。** 先从用户入口验证行为，再选择与改动对应的检查。改解码或分页，用合成样书比较正文和锚点；改持久化，覆盖短写、损坏与重开；改预读，覆盖连续点按、停读再翻、跨章、跳章及关闭。桌面检查正确性，板端记录输入到刷完的耗时、峰值和关闭后的可用堆。性能对照固定固件基线、书、位置、字体、字号、全刷周期及冷热缓存，写明样本数和慢页所在位置。
- **开书与预读的验收边界。** 分别标注设备从原书冷建索引、已有 TF 索引后重开、下一页已在 RAM 预排三种条件；电脑生成的索引注明来源。声称改善首次开书时，在独立测试目录或测试卡上从无派生索引走到首屏，核对正文或目录目标。分析慢页时拆出面板 BUSY 与此前各阶段耗时。主机限单块申请只覆盖受控的分配入口，性能结论以真机为准。

## 如何用规范审查现有代码

| 涉及的改动 | 如何验收 |
| --- | --- |
| 拆分页面或控件 | 从触屏与侧键走相同阅读意图，核对画面和阅读位置。页面调用同一份导航和存储规则。 |
| 修改 EPUB 冷建或内存准入 | 分开验证无索引、已有索引和损坏索引。抽查首屏、目录目标、报错原因和关闭后的内存。 |
| 修改导入工具 | 用原始输入核对设备可读格式、截断及越界行为。纯目录迁移应保持已有数据字节和用户路径兼容。 |

评审先问：这项改变会让读者多等多久，又会在最紧张的时候额外占用多少 RAM？涉及热路径就给出对照结果。再检查规则由谁维护、不同入口如何保持一致、失败或取消后谁释放资源并保住进度。对已有代码的逐项评审记录保存在本地审核区；正式文档只保留稳定的规则和示例。

## 分享前验收

1. 核对 Git 实际跟踪的文件。对卡包独立解包，按 tf/manifest.json 比对条目集合和文件内容。在临时工作副本放一个清单外的字体或文本，打包后确认 ZIP 里没有它。自有代码的发布许可由作者确定，第三方许可随相应源码或素材分发。
2. 从本地干净克隆运行 `./tests/run.sh` 和 `./scripts/build.sh`。目录重组涉及随卡文件时，从打包产物解到临时卡目录，至少实际打开一份显式选中的样书和字体，并读取示例课包。断言预期样例确实被执行，避免目录搬迁后遍历到零个文件仍然通过。可选内容的完整性由发行清单校验；核心功能回归使用可公开的固定样例。
3. README、AGENTS 和 docs 的入口必须存在。目录迁移与功能优化分别可审查。源码可构建、本地提交、推送和公开发布是不同的交付状态。
4. 发布板端镜像时，按支持机型与分区表校验镜像类型、容量和目标槽。安装说明写明该镜像的适用布局、写入范围与启动恢复步骤；真机安装后读回版本并确认首页启动。

参照：[PlatformIO 目录配置](https://docs.platformio.org/en/latest/projectconf/sections/platformio/options/directory/index.html)。本项目使用 TF 作为可移除介质，不把 TF 内容误作 PlatformIO 的片上文件系统 data 目录。
