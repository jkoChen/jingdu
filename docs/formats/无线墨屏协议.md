# 无线墨屏 HTTP 协议 v1

从设备的「设置 → 无线墨屏」进入，点画布中央查看本机地址与密钥。以下地址和密钥仅作请求格式示例。


只有一个写入口。每次请求都描述**完整的下一屏**，以最后一份完整、验证通过的请求为准。端口为 8080，与现有文件服务分开。无线墨屏可在无 TF 卡时独立启动，仅开放显示权限。

```http
PUT /api/v1/screen HTTP/1.1
Host: jingdu-example.local:8080
X-Jingdu-Key: DEMO
Content-Type: text/plain; charset=utf-8
Content-Length: 12

构建完成
```

| 发送的内容 | 线上的表示 | 设备行为 |
| --- | --- | --- |
| 一句话或几行文字 | `text/plain; charset=utf-8`，UTF-8 原文，上限 4 KiB | 直接取固件内置的文泉驿 15 px 原生点阵，行距（行首到行首）24 px，左、上边距 16 px。无需 TF 卡，不打开阅读 TTF。共 7,542 个字符（含 6,763 个汉字）；字库外字符显示 □。保留换行，按字宽折行，整屏放不下返回 `422` 并保留原画面。需要生僻字或自定字体时，发送端可排成 PBM。 |
| 已经排好的整屏 | `image/x-portable-bitmap`，单张 240 × 416 的二进制 PBM（P4） | 按像素显示，占满整屏。字体、图片、线条、留白和角落都由发送端决定。 |
| 白屏 | 同一入口，`text/plain`，请求体为零字节 | 清空画布，继续接收。 |

v1 选用 PBM 的最小子集。固定 ASCII 文件头为 `P4\n240 416\n`，其后紧跟 12,480 字节像素，共 12,491 字节。每行 30 字节，从上到下、从左向右，每字节最高位在左，1 表示黑色。发送端可以直接产生这 11 字节的头和像素数据。设备内部画布的位极性相反，接收时逐字节取反。[Netpbm 的 PBM 格式及最小子集](https://netpbm.sourceforge.net/doc/pbm.html) · [静读画布实现](../../src/ui/Canvas.cpp)

**一次配置，两种调用。** 将连接信息页的地址存为 `JINGDU_URL`（含 `http://` 和端口），将密钥存为 `JINGDU_KEY`。下列命令可直接调用固件。

```sh
curl --fail -X PUT "$JINGDU_URL/api/v1/screen" \
  -H "X-Jingdu-Key: $JINGDU_KEY" \
  -H 'Content-Type: text/plain; charset=utf-8' \
  --data-binary '构建完成'

curl --fail -X PUT "$JINGDU_URL/api/v1/screen" \
  -H "X-Jingdu-Key: $JINGDU_KEY" \
  -H 'Content-Type: image/x-portable-bitmap' \
  --data-binary @screen.pbm
```

清屏时将第一条命令的末项改为 `--data-binary ''`。这个版本使用局域网 HTTP，密钥随请求明文传输，适用范围为可信局域网。密钥只在本机信息页可查看，与文件服务的配对凭据分开。
